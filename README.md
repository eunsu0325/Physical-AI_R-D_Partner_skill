# Physical AI R&D Partner

### 한국어 피지컬 AI 연구개발·유지보수 파트너

**현장에서 본 문제를 출발점으로 AI와 원인을 의논하고, 코드 수정·실험·검증까지 함께 진행하기 위한 Codex 스킬입니다.**

정확한 알고리즘 이름이나 완성된 개발 명령을 몰라도 괜찮습니다. “손이 상자보다 위로 가는데 왜 그런지 모르겠어”처럼 현재 상황을 설명하면, AI가 접근 가능한 코드·문서·로그를 확인하고 근거와 다음 행동을 구체화하도록 안내합니다. 사용자는 관찰과 목적, 제약과 의견으로 연구에 참여합니다.


설치가 완료됐다는 응답과 설치 위치를 확인하세요. 다음 메시지부터 `$physical-ai-rnd-partner-ko`로 호출할 수 있습니다. 설치 목록에 나타나지 않으면 Codex를 다시 시작하고 확인하세요.

GitHub에서 README를 읽거나 저장소를 clone하는 것과 Codex에 스킬을 설치하는 것은 별개입니다. 팀원도 자신의 Codex 환경에 한 번 설치해야 합니다. `SKILL.md`만 복사하면 참고문서가 빠지므로 폴더 전체가 필요합니다.

이 스킬은 텍스트 지침과 참고문서입니다. **설치 자체에는 GPU·ROS·시뮬레이터·모델 가중치가 필요하지 않습니다.** 실제 연구 코드를 실행할 때는 해당 프로젝트의 환경과 권한을 확인합니다.

### 2. 작업할 연구 프로젝트 열기

설치가 끝나면 Codex에서 **실제로 조사하거나 수정할 연구 프로젝트**를 엽니다. 이 저장소는 스킬 배포용이며, 사용자의 로봇 코드나 학습 프로젝트는 별도로 존재합니다.

사용할 코드·문서·로그가 다른 위치에 있다면 그 위치를 알려주세요. 회사 GPU 서버에서만 실행할 수 있다면 그 조건도 함께 설명하면 됩니다. 서버 접속이 되지 않는 상태에서는 준비한 코드·명령과 실제 실행 결과를 구분하도록 설계했습니다.

### 3. 파일을 바꾸지 않는 첫 호출로 확인하기

작업할 프로젝트를 연 상태에서 다음 메시지를 입력해 보세요.

```text
$physical-ai-rnd-partner-ko

이번에는 조사와 설명만 하고 파일 수정·설치·학습·장비 동작은 하지 마.
```

첫 사용에서는 다음을 확인하면 됩니다.

- 현재 연 프로젝트의 실제 파일·경로를 근거로 설명하는가?
- 확인한 내용과 아직 모르는 내용을 구분하는가?
- 요청한 조사 범위 안에서 다음 확인과 이유를 제시하는가?

파일을 읽을 수 없다면 무엇이 필요한지와 그 이유를 안내해야 합니다. 이 호출은 프로젝트 접근과 협업 흐름을 확인하는 예시이며, 답변 한 번으로 코드의 정확성이나 연구 성과가 검증되는 것은 아닙니다.

## AI와 어떻게 연구하나요?

사용자가 관찰·목적·제약을 제공하면 AI는 접근 가능한 자료 조사, 원인 후보와 대안 비교, 요청된 변경과 검증을 수행합니다. 추천 이유와 추천을 바꿀 증거를 설명하고, 결과를 사용자와 함께 해석하도록 설계했습니다.

| 현재 상황 | 함께 진행할 일 |
|---|---|
| 어디부터 볼지 모르겠다 | 자료에서 관찰·목표·미정을 정리하고 다음 확인과 이유 제안 |
| 내 원인 추측이 맞는지 모르겠다 | 사실과 가설을 구분하고 대안·반례·판별 방법 비교 |
| A와 B 중 선택해야 한다 | 실제 자원·관측·입출력·검증 비용에 맞춰 선택 조건 비교 |
| 코드를 구현하거나 고쳐야 한다 | 실행 경로를 읽고 필요한 변경·검증 수행 |
| 학습 결과가 좋아졌는지 모르겠다 | 기준·분모·평가 조건·실패·변동·기존 능력 회귀 확인 |
| 어제 되던 시스템이 안 된다 | 현재 실행 버전·환경·설정과 직전 정상 기준 연결 |
| 다른 컴퓨터나 GPU 서버에서 이어야 한다 | 필요 파일·실행 위치·명령·결과 회수·미실행 조건 정리 |

필요하면 본 현상, 원하는 변화, 이미 시도한 것, 사용할 자료와 실행 환경을 알려주세요. 모르는 항목은 모른다고 말해도 됩니다. AI가 먼저 확인할 수 있는 자료를 조사하고, 사람의 현장 관찰이 필요한 부분만 구체적으로 질문하도록 했습니다.

### 의견이 바뀌면 계획도 바꿉니다

다음은 협업 방식을 보여주는 가상 예시입니다.

**사용자:** 상자를 놓치는데 그립을 더 세게 학습하면 될까?

**AI:** 힘 부족은 원인 후보야. 먼저 기존 기록에서 처음 어긋나는 시점이 접촉 전인지 후인지 확인하겠어. 두 경우는 우선 볼 관측·좌표·접촉·제어 경계가 달라.

**사용자:** 다시 보니 닿기 전부터 손이 상자보다 위에 있어.

**AI:** 그러면 파지 후 힘 부족보다 물체 기준점·좌표 변환·관측 시점과 손 목표를 먼저 확인할 근거가 생겼어. 원래 위치→변환 후 위치→정책 입력→목표 출력 경로를 비교하고, 그 결과로 수정이나 추가 학습을 결정하자.

접근 가능한 자료가 있으면 실제로 확인하며, 위와 같은 계획과 도구로 수행한 결과를 구분합니다. 자세한 예시는 [협업과 결정](skills/physical-ai-rnd-partner-ko/references/collaboration-and-decisions.md)에 있습니다.

## 결과를 읽을 때 확인할 것

스킬은 확인한 범위에 맞춰 결론을 내리도록 안내합니다.

| 관찰한 결과 | 추가로 판단할 부분 |
|---|---|
| mock 테스트 통과 | 실제 정책·장치 경로도 확인했는가? |
| loss 감소·체크포인트 생성 | 목표 행동과 작업 지표가 개선됐는가? |
| 교사/플래너 개입이 있는 성공 | 정책 단독의 수행 능력은 어떠한가? |
| SIM·영상 재생 성공 | 실제 센서·제어·물리 조건에서도 확인했는가? |
| 성공 사례 하나 | 실패와 반복 변동을 포함해 비교했는가? |

보고에는 바뀐 행동과 확인 결과, 이유, 실제 검증, 한계와 다음 판단이 연결돼야 합니다. 코드·설정·데이터·가중치·자산·환경·명령·결과 경로는 필요한 재현 단위로 남깁니다. 작은 수정에 전체 재학습이나 대형 MLOps 도입을 요구하지 않습니다.

## 수동 설치와 업데이트

### 직접 복사하기 · macOS/Linux

위의 Codex 설치 요청을 쓰기 어려울 때 사용할 수 있습니다. 아래는 Git과 POSIX 호환 셸 기준입니다.

```bash
git clone https://github.com/eunsu0325/Physical-AI_R-D_Partner_skill.git
cd Physical-AI_R-D_Partner_skill

mkdir -p "$HOME/.agents/skills"
if [ -e "$HOME/.agents/skills/physical-ai-rnd-partner-ko" ]; then
  echo "이미 설치된 사본이 있습니다. 위치와 개인 수정을 확인한 뒤 업데이트하세요."
else
  cp -R skills/physical-ai-rnd-partner-ko "$HOME/.agents/skills/"
fi
```

수동 개인 설치의 `~/.agents/skills` 예시와 내장 설치기가 사용하는 환경별 위치는 다를 수 있습니다. 기존 설치가 `~/.codex/skills` 등에 있으면 그 위치부터 확인해 한 사본을 관리하세요. 다른 위치에 같은 이름을 중복 설치하면 선택 목록에 함께 나타날 수 있습니다. [공식 스킬 문서](https://learn.chatgpt.com/docs/build-skills)

특정 프로젝트에서만 쓰려면 해당 프로젝트의 `.agents/skills/physical-ai-rnd-partner-ko/`에 폴더 전체를 복사합니다. 팀 프로젝트에 이 폴더를 커밋하면 프로젝트 범위의 스킬을 함께 관리할 수 있습니다. 개인 설치와 프로젝트 설치 중 필요한 범위를 선택하세요.

Windows에서는 사용자 홈 또는 프로젝트의 스킬 위치에 같은 폴더 구조로 복사하세요. 위 POSIX 명령을 PowerShell에서 그대로 실행하는 방법은 검증하지 않았습니다.

최종 폴더 구조는 다음과 같습니다.
