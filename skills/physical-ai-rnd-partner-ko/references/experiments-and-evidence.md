# 실험·평가·증거를 연결하기

## 확인할 질문과 비교를 맞춘다

smoke는 실행·입출력 경로, 회귀 검사는 특정 결함의 재발, 효과 평가는 후보가 기준보다 목적을 더 잘 달성하는지를 다룬다. 어떤 증거가 필요한지 질문에 맞춰 고른다. 작은 코드 수정에 모델 재학습을 의무화하거나, mock 테스트를 실제 정책의 작업 성공으로 사용하지 않는다.

실험을 시작할 때 기존 기록에 필요한 항목을 연결한다. 새 파일이나 고정 양식을 매번 만들 필요는 없다.

| 항목 | 판단할 내용 |
|---|---|
| 질문/가설 | 어떤 현상을 설명하거나 개선하려는가? 다른 원인이면 어떤 관찰이 달라질까? |
| 기준/변경 | 어떤 코드·모델·데이터·설정을 비교하고 무엇이 함께 달라지는가? |
| 측정 | 성공 기준·단위·분모·시간 구간·실패/중단·교사 개입을 어떻게 기록하는가? |
| 반복/일반화 | 독립 학습 run, 평가 episode, 장면/물체, frame 중 무엇을 반복하는가? |
| 자원/중단 | 실행 위치·예산·실패 중단·검토 시점·남길 결과는 무엇인가? |

목표·허용 오차가 미정이면 작업용 초안을 제안하고 그 기준이 어떤 결정을 바꾸는지 설명한다. 비교 후 유리한 허용 오차로 바꾸거나 실패 시도를 조용히 빼지 않는다. 실패 유형을 별도 분석할 수 있으나 전체 분모와 조건부 지표의 의미를 보존한다.

원인을 좁히는 디버깅에는 작은 변경이 유용하다. 요인의 효과가 서로 의존하면 적절한 조합 비교·DOE를 검토한다. ‘언제나 한 요인만’이나 ‘항상 전체 조합’을 만능 절차로 삼지 않는다.

## 평가를 오염시키지 않는다

주장하는 일반화의 대상을 정한다. 새 episode/session/물체/장면에 대한 평가라면 같은 원본의 근접 frame·증강본·파생 자료가 train/test를 가로지르는지 확인한다. 학습되는 정규화·특징 선택·전처리는 training 부분에서 fit하고 평가에서는 고정 적용하는 경로를 확인한다. 의도된 온라인 적응/통계 갱신을 평가하는 프로토콜이라면 사용할 수 있는 정보·적응 시점·비용을 명시해 별도로 비교한다.

분할 방식은 질문에 맞춰 고른다. 항상 시간순/물체별로 나누지 않는다. 같은 장면 안에서만 시험한 결과를 새 장면 성능으로 바꾸어 보고하지 않는다. 높은 점수나 무작위 frame 분할 하나만으로 누출을 확정하지도 않는다.

개발·튜닝·체크포인트 선정에 사용한 조건과 보류 평가를 구별한다. 평가 결과를 보고 다시 수정하면 그 결과가 개발 과정에 사용됐음을 밝힌다. baseline과 후보의 데이터·예산·선정 규칙·교사/플래너 보조 조건을 비교 가능하게 한다. 묶음 변경의 기여를 나누지 못하면 그 한계를 남긴다.

## 반복과 불확실성을 읽는다

학습 seed를 고정한 재실행, 독립 학습 run, 같은 정책의 여러 episode는 다른 단위다. 수천 frame을 수천 독립 실험처럼 세지 않는다. 장치·라이브러리·시뮬레이터의 비결정성과 초기 조건도 기록한다. 작은 n이면 개별 결과와 조건을 보존하고 잠정적으로 판단한다.

반복 횟수와 분석은 예상 효과·변동·비용·잘못된 판단의 영향을 보고 정한다. 정해진 seed 수나 다중 벤치마크의 IQM/stratified bootstrap을 단일 작업에 자동 적용하지 않는다. 소수 run의 구간을 정밀한 보증처럼 제시하지 않는다. 두 신뢰구간의 겹침만으로 차이의 존재·부재를 결정하지 않는다.

모든 실행 결과와 주요 실패를 남긴다. 평균 주지표와 함께 충돌·낙하·최대 오차·실행시간·계산비용·기존 능력 중 관련 회귀를 본다. 대표 성공/실패 영상과 원시 로그를 연결한다. 실패한 가설을 기각한 것도 유용한 결과다.

## 실행 비용과 끝을 정한다

실제 실행 대상과 자원을 확인한 뒤 작은 smoke나 짧은 기준 실행으로 비용을 추정한다. 큰 학습·데이터 생성은 허용된 자원 범위에서 수행한다. 시간/시도/비용 중 필요한 상한, NaN·필수 로그 파손 등 실패 조건과 다음 검토 시점을 정한다. 좋은 결과가 나올 때까지 자동 연장하지 않는다. 결과가 결정을 바꾸지 못하고 예산이 소진되면 판단 보류와 다음 선택을 보고한다.

이미 승인된 배치 안의 반복마다 새 승인을 요구하지 않는다. 자원·목적·장비 동작 범위를 실질적으로 바꾸는 경우에는 기존 허용 범위를 확인한다. 사람 작업시간·GPU 시간·전체 경과시간·동시 작업 수를 구별하며 병렬 시간을 단순 합산해 생산성 향상으로 주장하지 않는다.

## RL 학습 경로를 고칠 때 필요한 의미 검사

일반 테스트를 통과해도 잘못된 학습 표적은 계산될 수 있다. 관련 변경이라면 reward·관측 이력·정규화·reset·종료/시간 제한·최종 관측·bootstrap 마스크·실제 optimizer update의 의미를 실제 구현에서 확인한다.

MDP의 terminal state에 도달한 종료와 외부 실행 제한에 따른 truncation은 다를 수 있다. 많은 TD 방법에서 두 경우의 bootstrap 처리가 다르다. 유한 시간 자체가 작업 정의에 포함되는 경우도 있으므로 모든 timeout을 truncation으로 바꾸지 않는다. auto-reset/vector API가 주는 최종 관측과 새 episode 관측도 버전별로 확인한다. 특정 프레임워크의 API를 모든 저장소에 이식하지 않는다.

## 증거 범위의 예

‘테스트18개 통과, loss 감소, SIM 영상1개’는 그 세 관찰이다. mock 정책이면 실제 정책 추론은 미확인이고, 교사가 출력을 덮어썼다면 정책 단독 성공과 구별한다. 실패를 제외한 성공률이나 더 넓어진 허용 오차는 같은 기준의 개선 증거가 아니다. 실물 상태 수신과 실제 명령 전송·폐루프 작업도 별도 확인한다.

AI가 작성한 테스트는 실행 증거가 될 수 있으나 자동으로 독립된 정답은 아니다. 가능하면 명세·작은 손계산·물리 불변량·공식 예제·보류 데이터·실제 관찰처럼 다른 근거 경로와 대조한다. 없는 근거는 미확인으로 남긴다.
